# UI 說明內容指引

## 本輪盤點

目前主要說明內容集中在排行榜、設定、借用與管理表單。排行榜原本把排名依據直接放在頁面摘要，容易讓主要內容變得冗長；本輪已將完整的四項排行規則移至「排行說明」對話框，頁面只保留「探索社團裡受歡迎的桌遊！」等簡短介紹。

設定與安全提醒、表單欄位錯誤及危險操作確認仍應直接顯示，因為這些內容需要使用者在當下理解或採取行動。管理端的長篇操作規則適合保留在表單附近，必要時再以可展開區塊整理，避免把錯誤或必要條件藏進 Tooltip。

## 顯示方式建議

| 內容 | 建議方式 | 原因 |
| --- | --- | --- |
| 簡短名詞定義 | Tooltip 或旁邊的 Info 按鈕 | 內容短，且不影響主要閱讀流程；必須支援鍵盤與觸控。 |
| 多項規則與完整排行依據 | Modal | 使用者主動查看，適合長內容與行動版捲動。 |
| 欄位驗證、權限不足、操作失敗 | 行內錯誤或 Alert | 需要立即理解，不能只放在暫時通知。 |
| 刪除、註銷等危險操作 | Confirm Dialog | 需要明確確認，不應以 Tooltip 取代。 |
| 一次性成功回饋 | Toast | 不佔頁面高度，也不干擾後續操作。 |

## 全站一致性原則

1. 主要頁面先呈現任務與結果，技術規則、完整定義與補充背景放在按需開啟的介面。
2. 不在一般使用者畫面使用 SQL、Repository、權重、資料投影等實作術語；隱私、權限與必要條件仍要清楚說明。
3. Tooltip 不能只支援 Hover；資訊必須能以鍵盤和觸控裝置取得，且不承載關鍵錯誤或必要操作。
4. Modal 必須有語意標題、可關閉、可捲動，並在關閉後將焦點返回觸發按鈕。
5. 行內說明與錯誤應靠近對應控制項，避免重複相同文字或留下空白占位。

## 後續優先級

- 高：檢查公開頁面是否把隱私、權限或資料範圍寫成技術術語。
- 中：整理管理表單中重複的長篇說明，保留必要條件並將背景資訊改為可展開內容。
- 低：統一 Tooltip、Popover 與 Modal 的按鈕命名、焦點行為與間距 token。

本文件只記錄盤點與指引；除排行榜說明對話框外，本輪不修改其他頁面。
