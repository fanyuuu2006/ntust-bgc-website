# 管理總覽

管理總覽先顯示需要處理的借用，再顯示桌遊社產概況。數量由 server service / repository 查詢，不在瀏覽器下載全部紀錄後計算。

| 工作 | 條件與排序 |
| --- | --- |
| 待審核借用 | pending，申請時間由舊到新 |
| 等待領取 | approved，申請時間由舊到新；資料模型沒有獨立核准時間 |
| 已逾期 | borrowed 且 due_at 小於查詢當下時間，歸還期限由早到晚 |
| 借出中 | borrowed，歸還期限由早到晚，包含已逾期紀錄 |

逾期不是新的資料庫狀態。清單 URL 使用 `status=borrowed&overdue=true`，Repository 在分頁前篩選；`due_at` 為空不算逾期。數量與清單各自在查詢當下計算，跨頁期間若有歸還或跨過期限，數量可能自然改變。未定義即將到期門檻，因此不新增該統計。

## 最近驗證信

已驗證帳號只顯示帳號驗證狀態與驗證時間，不再查詢最近連結。未驗證帳號顯示最近建立時間、到期時間與有效／已過期／已停用。

目前 `consumed_at` 同時用於驗證及重寄取代，不能區分原因；「已停用」不代表帳號已驗證。建立紀錄也不代表信件已送達。頁面不提供 token、hash 或人工驗證操作。

## 結構檢查與人工驗收

- 320／375px：三張獨立白底卡片排列為緊湊單欄，逾期為下方提醒列；使用者 avatar 固定大小，名稱／Email 可換行，學籍雙欄可縮小，建立時間與查看按鈕可換行。
- 平板：三個借用階段並排；使用者仍使用卡片。
- 桌面：三個借用階段並排，逾期不作為第四個階段；使用者表格以 avatar、帳號及真實姓名組成身分欄。表格溢出由既有 AdminListSection 內部承擔。
- 結構與元件測試不能證明瀏覽器無 overflow；人工驗收請使用長中英文名稱、長 Email 與系所，確認文件寬度、卡片與操作按鈕。
- 由管理總覽進入各借用篩選，切換逾期／其他狀態，確認搜尋、排序、pageSize 保留且 page 重設為 1。

## 下一階段：公告內容（僅稽核）

`supabase/schema/canonical-public-schema.sql` 的 `announcements.content` 為 `text not null`，TypeScript 為 string。`src/app/(public)/announcements/[id]/page.tsx` 直接透過 React 文字節點及 `whitespace-pre-wrap` 呈現，現有內容是純文字。

本輪不引入 Rich Editor 或 migration。下一階段需先決定內容格式與舊純文字相容策略，不能直接把既有內容當 HTML 解讀。

## 視覺收斂驗收

保留網站圓角、字級與小型圖示；借用階段使用三張獨立白底卡片，不再有外層 Card 或整片色底，逾期為下方獨立提醒列。管理總覽不新增概況查詢，只保留緊湊社產數量。

- 桌面：與 `/profile`、`/dashboard`、`/memberships` 並排查看，確認圓角、字級、淡色與區塊節奏一致；不是四張 KPI Cards。
- 逾期 0／大於 0：提醒列皆可見，只有有逾期時增加警示強調。
- 375px（再補 320px）：階段以緊湊列呈現，連結可點選、可換行，無文件水平溢出。
- 四個借用 CTA 的 query 保持 Phase 3D 原值。

以上為 source／結構檢查及人工驗收清單，並非瀏覽器視覺 PASS。
